# StudyFlow AI 产品需求文档（PRD）

版本：v1.0　状态：待评审　作者：产品部

---

## 1. 产品概述

### 1.1 问题定义

| 痛点 | 表现 | 后果 |
|---|---|---|
| 认知过载 | 教材厚、目录乱，不知道从哪一章开始 | 迟迟不开始，用「先整理资料」替代真实学习 |
| 情绪内耗 | 越学越怀疑「有没有用」，焦虑转化为摆烂 | 断学 3 天以上，复习节奏崩塌 |
| 反馈缺失 | 做完题不知道错在哪、掌握到什么程度 | 重复犯同类错误，无法收敛 |

### 1.2 产品定位

面向备考人群的**智能题库与学习陪伴系统**：把教材结构化为可练习的知识点，用学情数据驱动 AI 在正确的时间介入，把焦虑拆成 5 分钟内可完成的动作。

### 1.3 产品结构

```
科目 → 章节 → 知识点 → 母题 → 变题
```

三个核心页面：AI 对话（主入口）、分类管理、知识库。

### 1.4 本期不做

社交 / 排行榜、付费体系、多人协作、主观题自动批改、移动端原生 App。

---

## 2. 产品目标

### 2.1 北极星指标

**周有效学习用户数**：一周内至少完成 1 次答题且产生 1 条学情数据的用户。

### 2.2 支撑指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 行动卡片完成率 | 触发的行动卡片中被点击完成的比例 | ≥ 40% |
| 焦虑后回流率 | 情绪对话后 24 小时内产生答题行为的比例 | ≥ 30% |
| PDF 解析成功率 | 上传文档成功产出章节树的比例 | ≥ 90% |
| 出题采纳率 | 生成的题目被保留、未被报错的比例 | ≥ 95% |
| 7 日留存 | 注册后第 7 天仍有学习行为 | ≥ 25% |

### 2.3 阶段目标

- 第一阶段：跑通「上传教材 → 出题 → 刷题 → 错题 → AI 感知」闭环
- 第二阶段：用数据证明 AI 介入能提升学习连续性
- 第三阶段：扩充题型与多科目覆盖

## 3. 用户画像

| 画像 | 特征 | 核心诉求 | 典型场景 |
|---|---|---|---|
| 考研党·小林（主力） | 大三 / 应届，全职备考，资料多、计划乱 | 把厚书拆成今天能做的几道题 | 打开 PDF 不知道从哪看；刷题后不知道薄弱点 |
| 在职备考·张姐 | 每天可支配 1～2 小时，碎片时间 | 5 分钟内能启动，不浪费通勤时间 | 晚上只剩 40 分钟，纠结先复习还是先做题 |
| 二战焦虑型·阿凯 | 有基础但信心崩，容易中断 | 情绪被接住，且有具体动作 | 连续答错后否定自己，直接关掉 App |

共同特征：对「宏大规划」免疫，对「具体下一步」敏感；对 AI 说教反感，对数据化反馈信任。

## 4. 核心功能详细描述

### 4.1 AI 情感助手与行动指令卡片

**功能目标**：把情绪问题转成可点击的一步行动，不做纯安慰。

**触发条件（满足任一）**

| 类型 | 规则 |
|---|---|
| 显式表达 | 用户输入含焦虑、迷茫、放弃、没用、要不要继续等语义（对话模型判定） |
| 行为信号 | 同一知识点连续答错 ≥ 3 题 |
| 中断信号 | 连续 2 天无学习行为后再次进入 |

**输入上下文**：当前科目、最近 7 天正确率、薄弱知识点 Top3、连续答错记录、待复习题数量。

**交互流程**

1. 用户表达焦虑 → AI 先共情（1 句），承认这种感受正常
2. 指出问题过于宏大，给出微观选择（查资料 / 倾诉 / 先休息）
3. 输出**行动指令卡片**，而非纯文本建议

**行动指令卡片结构**

| 字段 | 说明 |
|---|---|
| 标题 | 一句话动作，如「完成最简单的 2 道题」 |
| 时长 | 预估 5 分钟内 |
| 类型 | 刷题 / 看解析 / 复习错题 / 查资料 |
| 跳转 | 题目 id 或知识点 id，点击直达 |
| 状态 | 待完成 / 已完成 / 已忽略 |

**生成规则**

- 必须引用真实学情数据：优先取当前科目正确率最低且题量 ≥ 3 的知识点
- 单次只发 1 张卡片，避免选择负担
- 每日最多触发 2 次，同一用户 4 小时内不重复同类卡片

**异常处理**

| 异常 | 处理 |
|---|---|
| 无学情数据 | 降级为「完成 2 道新题」，不引用不存在的薄弱点 |
| 卡片指向的题目已删除 | 后端校验失败，重新生成一张 |
| 用户连续忽略 2 次 | 停止推送情绪卡片 24 小时，改为普通回复 |
| 模型输出无卡片结构 | 服务端兜底模板：一句共情 + 默认卡片 |

---

### 4.2 PDF 智能解析出题

**功能目标**：上传教材即产出可用章节树与练习题，不要求用户手工录入。

**流程**

1. 用户上传 PDF / TXT / MD（≤ 500MB）
2. 系统同步完成文字抽取与质检，异步执行章节识别与出题
3. 前端显示任务进度，完成后展示章节树与生成题数
4. 用户确认后写入题库，不确认不入库

**任务状态机**

```
pending → extracting → structuring → generating → done
                                        └→ failed（可重试）
```

| 状态 | 前端表现 |
|---|---|
| pending | 排队中，显示队列位置 |
| extracting | 抽取文字，百分比按页数 |
| structuring | 识别目录 / 章节树 |
| generating | 按知识点生成题目，显示已生成数 |
| done | 展示结果，进入确认页 |
| failed | 错误原因 + 重试按钮（最多 3 次） |

**交互与规则**

- 进度轮询：每 2 秒一次，连续失败退避到 5 秒；页面切后台暂停轮询，回到前台恢复
- 章节树可编辑：改名、合并、删除分支，再确认生成
- 题目类型：单选、多选；每题必须带答案与解析
- 题量上限按知识点配置，单章默认 ≤ 20 题

**异常处理**

| 异常 | 处理 |
|---|---|
| 扫描版 PDF（无文字层） | 抽取阶段直接失败，提示「疑似扫描版，请上传带文字层的文件或先 OCR」 |
| 目录缺失 | 按版面标题与字号推断章节，输出后提示「目录为自动推断，请核对」 |
| 模型超时 / 返回非法结构 | 任务失败，保留已抽文本，重试只重跑生成阶段 |
| 文件超限 | 上传阶段拒绝，提示上限 |
| 重复上传同一文件 | 按文件哈希去重，复用已完成结果 |
| 用户中途关闭页面 | 任务继续，重新进入时按任务 id 恢复进度 |

---

### 4.3 刷题与判定

**流程**

1. 进入做题模式，逐题展示题干（Markdown + 公式 + 插图）
2. 作答（单选 / 多选），提交
3. 即时反馈：对错、正确答案、解析
4. 记录作答结果，写入学情数据；答错自动进错题本

**规则**

- 单选：选项全等即正确；多选：集合相等才算正确，少选多选均判错
- 提交幂等：同一题目同一会话重复提交只记一条有效作答
- 判定结果不依赖客户端，服务端为准
- 答错时必须选择错因（概念不清 / 计算失误 / 审题错误 / 记忆模糊），可跳过

**异常处理**

| 异常 | 处理 |
|---|---|
| 题目无答案或答案缺失 | 展示「该题缺少答案」，不计入学情 |
| 提交超时 | 前端提示重试，服务端保证不重复计分 |
| 题目被删除 | 返回 404，退出做题并提示 |

---

### 4.4 学情数据与错题本

**功能目标**：让用户和 AI 用同一套数据说话。

**数据模型**

| 数据 | 计算方式 |
|---|---|
| 知识点掌握度 | 正确率（对 / 对+错）与稳定性（最近 10 次正确率）加权，0–100 |
| 科目雷达图 | 按章节聚合知识点掌握度 |
| 错题本 | 答错的题目自动归集，按知识点分组，支持标记已掌握 |
| 待复习 | 错题按间隔递增排期（错 → 次日；连对 → 间隔翻倍） |

**交互**

- 分类页面提供「学情」入口：雷达图 + 薄弱知识点列表 + 错题本
- 每次答题后即时更新，不做定时任务
- 学情数据通过内部接口提供给 AI 助手，作为情绪触发与行动卡片的上下文

**异常处理**

| 异常 | 处理 |
|---|---|
| 样本不足（作答 < 3） | 显示「数据不足」，不计算掌握度，不用灰色百分比误导 |
| 全对或全错 | 掌握度封顶 100 / 0，稳定性单独展示 |
| 科目无题目 | 空状态引导上传教材 |

---

### 4.5 逆向反馈（题目报错）

**功能目标**：出题质量不可控，必须给用户纠正通道。

**入口**：题目卡片与做题页均提供「报错」。

**报错分类**：题干错误、答案错误、解析错误、重复题目、知识点归属错误、其他（附文本）。

**流程**

1. 点击报错 → 选择类型 + 补充说明
2. 提交后题目标记「疑似问题」，本人题库内该题暂停进入推荐与行动卡片
3. 状态流转：待处理 → 已修正 / 已忽略
4. 聚合统计报错率，作为出题质量的度量

**异常处理**

| 异常 | 处理 |
|---|---|
| 同一题重复报错 | 合并为一条，记录次数 |
| 用户自己误报 | 支持撤回（24 小时内） |
| 报错后题目被删 | 保留报错记录，状态置为已失效 |

---

### 4.6 任务状态与轮询（通用能力）

适用于 PDF 解析、批量出题、批量导入。

- 所有长任务统一返回 `task_id`，前端只认任务状态，不做本地估算
- 轮询带上 `since` 游标，避免重复拉取
- 失败必须提供错误码与可执行建议，不只显示「失败」
- 任务记录保留 7 天，支持查询历史结果

## 5. 端到端关键流程

**流程 A：从教材到第一道题**

```
登录 → 上传 PDF → 轮询解析 → 编辑章节树 → 确认生成
→ 题库写入 → 引导做题 → 提交判定 → 学情更新
```

**流程 B：连续答错到情绪介入**

```
连续答错 3 题 → 服务端标记异常 → 下次进入对话
→ 注入学情上下文 → AI 共情 + 行动卡片
→ 点击卡片直达题目 → 完成 → 卡片状态更新 → 记入回流指标
```

**流程 C：报错到修正**

```
答题发现题目错误 → 报错（选类型）→ 题目置疑
→ 修正 → 状态已修正 → 恢复可推荐
```

## 6. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 页面首屏 ≤ 2s；对话首个响应 ≤ 4s；答题提交反馈 ≤ 500ms |
| 容量 | 单用户教材 ≤ 20 份，单文件 ≤ 500MB；题库 ≥ 1 万题不降级 |
| 可靠性 | 异步任务失败可重试且不产生半成品数据 |
| 安全 | 全接口鉴权，数据按用户隔离；越权统一返回 404 |
| 可观测 | 任务、对话、判定、报错四条链路均有结构化日志与错误码 |
| 兼容 | Chrome / Edge 最新版；窄屏 ≥ 1280 宽度可用 |

## 7. 埋点与验收

**必埋事件**：注册、登录、上传文件、解析完成 / 失败、确认生成、开始答题、提交作答、报错提交、情绪触发、卡片点击、卡片完成。

**上线验收（P0 全部满足才可发布）**

1. 上传带文字层 PDF，可在 5 步内产出可做题的章节树
2. 扫描版 PDF 明确失败并给出可执行建议
3. 单选 / 多选判定正确，错题自动进错题本
4. 连续答错 3 题后，对话侧能拿到学情并输出可点击卡片
5. 卡片点击可直达题目，完成后状态回写
6. 报错可提交、题目可置疑、可恢复
7. 两个账号数据完全隔离

## 8. 优先级与版本

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | 登录注册与数据隔离、PDF 解析出题、刷题判定、错题本、任务轮询 | 闭环地基，缺一不可 |
| P0 | 情绪触发 + 行动卡片 | 核心差异化 |
| P1 | 学情雷达图、报错处理后台、多选判定的错因统计 | 提升可信度 |
| P2 | 复习排期提醒、变题推荐自动入库、多科目模板 | 留存增强 |

---

## 9. 边界与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 出题质量不稳定 | 用户信任崩塌 | 报错通道 + 生成结果必须人工确认后入库 |
| PDF 版式复杂（公式、双栏） | 章节树错误 | 目录可编辑；公式题单独标注 |
| 扫描版无法解析 | 上传即失败 | 明示原因，给出 OCR 前置方案 |
| 情绪介入过度打扰 | 用户反感 | 频控 + 冷却 + 可关闭 |
| 学情数据样本不足 | 指标失真 | 不足 3 次不展示掌握度 |
| 长任务堆积 | 队列阻塞 | 单用户并发任务限制为 1 |

# 用户故事（User Stories）

## 模块一：账号与数据归属

- **US-01** 作为备考学生，我希望用用户名密码注册并直接进入系统，以便不用额外配置就开始学习。
- **US-02** 作为备考学生，我希望登录后看到自己上次的进度，以便不用重新找位置。
- **US-03** 作为备考学生，我希望刷新页面不掉线，以便不中断做题。
- **US-04** 作为备考学生，我希望我的科目、题目、教材只有自己能看，以便放心记录真实水平。

## 模块二：AI 情感助手与行动卡片

- **US-05** 作为焦虑的备考学生，我希望说出「学这些到底有没有用」时先被理解而不是被说教，以便情绪先落地。
- **US-06** 作为焦虑的备考学生，我希望 AI 给我一个 5 分钟内能做完的具体动作，以便马上有事可做而不是继续空想。
- **US-07** 作为情绪低落的学生，我希望这个动作是可点击的卡片并直接带我到题目，以便不用再自己找入口。
- **US-08** 作为连续答错的学生，我希望系统主动察觉到我的挫败并给出更简单的题，以便不至于直接放弃。
- **US-09** 作为用户，我希望 AI 的建议基于我的真实正确率和薄弱知识点，以便它说的是我的情况而不是套话。
- **US-10** 作为用户，我希望情绪提醒有频率限制且可以关闭，以便不被反复打扰。

## 模块三：PDF 解析与出题

- **US-11** 作为持有教材 PDF 的学生，我希望上传后系统自动识别章节树，以便不用手工录入目录。
- **US-12** 作为学生，我希望系统按知识点自动生成单选和多选题并附答案解析，以便节省出题时间。
- **US-13** 作为学生，我希望在生成前看到章节树并可以改名、合并、删除，以便纠正识别错误。
- **US-14** 作为学生，我希望生成结果经我确认后才入库，以便题库不被错误内容污染。
- **US-15** 作为学生，我希望能看到上传文件的去重结果，以便不重复解析同一份资料。

## 模块四：任务进度与失败重试

- **US-16** 作为上传大文件的学生，我希望看到解析到哪一步的进度，以便知道该等还是该走。
- **US-17** 作为学生，我希望解析失败时看到具体原因，以便知道是换文件还是重试。
- **US-18** 作为学生，我希望失败后能一键重试且不重复生成已有内容，以便不浪费已抽好的文本。
- **US-19** 作为学生，我希望关掉页面再回来还能看到任务结果，以便不因误关而重来。

## 模块五：刷题与判定

- **US-20** 作为学生，我希望进入做题模式逐题作答，以便专注在一道题上。
- **US-21** 作为学生，我希望提交后立刻知道对错并看到解析，以便当次就纠正理解。
- **US-22** 作为学生，我希望多选题少选或多选都判错，以便评分规则明确。
- **US-23** 作为学生，我希望答错时可以选择错因，以便区分「不会」和「粗心」。
- **US-24** 作为学生，我希望重复提交不会重复计分，以便统计数据可信。

## 模块六：学情数据与错题本

- **US-25** 作为学生，我希望看到每个知识点的掌握度，以便决定先补哪一块。
- **US-26** 作为学生，我希望用雷达图看各章节的强弱分布，以便一眼发现短板。
- **US-27** 作为学生，我希望答错的题自动进入错题本并按知识点分组，以便集中重做。
- **US-28** 作为学生，我希望错题按间隔安排复习，以便不靠记忆硬撑。
- **US-29** 作为学生，我希望样本不足时不要显示虚假百分比，以便数据可信。
- **US-30** 作为学生，我希望 AI 能看到我的学情数据，以便它理解我此刻的状态。

## 模块七：逆向反馈

- **US-31** 作为学生，我希望发现题目有错时能一键报错并选择类型，以便快速反馈。
- **US-32** 作为学生，我希望报错后该题暂时不再出现在推荐里，以便不被错误题消耗时间。
