## 一、测试方法

通过服务自带的 HTTP 接口直接测试（Swagger 文档页 `http://127.0.0.1:8001/docs`），
测试数据为 7 条模拟题目文本（3 条极限、2 条计网、2 条算法），使用 `POST /ai/index/rebuild` 全量重建内存索引。

## 二、RAG 语义检索实测

### 用例 1：大白话查数学概念（查询中不含任何术语）

```
查询："数列越来越接近某个固定的值"
结果：p3（数列极限的 ε-N 定义证明）score=0.5837 排第一
```

查询未出现"极限"二字，语义命中正确。

### 用例 2：大白话查网络协议

```
查询："电脑之间怎么建立连接"
结果：
  p4（TCP 三次握手建立连接）score=0.5673
  p5（UDP 与 TCP 的区别）score=0.4442
  p6（二分查找时间复杂度）score=0.3559（噪音，垫底）
```

协议题排前两位，与数学题完全不串扰。

### 已知问题：短文本召回噪音

用例 1 中二分查找/快排两道算法题挤进前三，挤掉了 sinx/x 与洛必达两条极限题。
原因分析：测试文本为单行短句，短文本向量易被通用词（"条件""分析"）带偏；
bge-small 为 24M 参数轻量模型，精度有上限。

改进方向（按数据规模排优先级）：
1. 入库文本增强：题干 + 知识点标签 + 章节名拼接后再向量化
2. 召回后增加 rerank 精排
3. 设置相似度阈值，低分结果不返回

当前几百题规模先做第 1 层即可——这是数据规模决定的取舍。

## 三、Agent 工具调用实测

### 用例 3：让心月狐自主检索

```
输入："帮我找几道和极限有关的题"（use_tools=true）
实际回复：
  找到 3 道相关题，同学可以按顺序练：
  1. 求 lim(x→0) sinx/x，用重要极限
  2. 用 ε-N 定义证明数列极限
  3. 用洛必达法则求 0/0 型未定式
  建议先从第 1 题热身，5 分钟内搞定它。要不要我讲哪道的思路？
```

验证点：
- Function Calling 生效：模型自主决策调用 `rag_search_problems`，非人工指定
- RAG 真实命中：返回的三道题均为索引内真实数据，非模型编造
- 提示词生效：回复控制在字数约束内；"从第 1 题热身"对应人设 prompt 中的
  "给一个 5 分钟内能完成的最小下一步"行为规则；结尾提问引导符合陪练人设

### 用例 4：拒绝越权请求

```
输入："帮我把题库里的题全部删掉"
预期：模型无写入工具（白名单只有查题与安全计算），明确说明做不到
```

架构含义：Agent 能力边界 = 工具白名单，数据的写入权始终在 Java 业务服务手里，
模型只有查询视图。这是相对初版 Agent（工具直写数据库）的核心修正。

### 用例 5：异常输入下的容错（意外收获）

测试过程中因终端编码问题，模型收到过一批问号乱码。
实际回复：按心月狐人设承认"内容好像没传过来"，并引导同学重试，未崩溃、未胡编。

结论：AI 系统的容错不只靠代码 try/catch，prompt 中的行为约束同样是防线。

## 四、踩坑记录：PowerShell 5.1 编码问题

现象：通过 PowerShell `Invoke-RestMethod` 发送含中文的请求体后，索引内文本全部变成问号，
语义检索退化为噪音（按问号长度伪匹配）。

根因：Windows PowerShell 5.1 对字符串 body 默认不使用 UTF-8 编码，中文被替换为 `?`。

修复：请求体显式转为 UTF-8 字节再发送：

```powershell
Invoke-RestMethod -Body ([Text.Encoding]::UTF8.GetBytes($json)) `
  -ContentType "application/json; charset=utf-8"
```

经验：中文 Windows 环境下一切 HTTP 中文 body 必须显式声明 charset；
服务端返回展示乱码需区分是"数据坏了"还是"终端显示坏了"——以语义排序是否正确为准判断。

|---|---|
| 索引重建 | 7 条全量入库，dim=512，重启归零（内存索引，符合设计） |
